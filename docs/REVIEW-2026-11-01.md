# DM Offline — internal pre-deployment security review

Date: 2026-11-01. Reviewer: Codex, the implementation agent. This is an internal engineering review with reproducible evidence, not an independent audit or a guarantee. No mainnet transaction was signed or broadcast during this review.

## Scope and release identity

Reviewed `Offline.sol`, `Admin.sol`, `SafeToken.sol`, `StockereumBinding.sol`, the deployment/preflight/recovery scripts, accounting specification and corresponding test suites. Stockereum's own security, the future token, wallet implementations and future website deployments are outside this review's certification scope.

Compiler: Solidity **0.8.38**, Cancun target, optimizer enabled with 10,000 runs, legacy code generation, metadata bytecode hash disabled. Offline runtime: **9,093 bytes**. Source and build fingerprints are recorded in [the release identity](REVIEW-2026-11-01.json); a subsequent source/config/compiler change requires a new review of that build.

## Round 1: manual accounting and authority review

Re-derived each funding's allocation as `funding × current account age / total current age`. Confirmed the two-index integration equals explicit per-funding accumulation, new deposits inherit no age, partial withdrawal removes proportional integer age, full exit clears active age and settled ETH survives exit. Fractional credit survives checkpoints. Funding rounds down and cannot allocate more than funded ETH. All money-changing paths are guarded; ETH payout applies effects before calling the recipient.

Reviewed the one-time official Hook binding, original creator checks, quote/fee/holder-reward settings, supply bound, two-step administrator changes and renunciation preconditions. There is no administrator withdrawal, arbitrary call, upgrade, principal seizure or withdrawal/claim pause. All contract money operations are O(1) in participant count; frontend enumeration is not part of settlement.

## Round 2: adversarial tests and independent accounting oracle

Added tests for six reentrant money entry points during ETH receipt; malicious ERC-20 callbacks during deposit/withdraw; taxed-deposit rollback including participant bookkeeping; failed ETH recipient recovery; admin transfer, cancellation, unauthorized calls and renunciation; incorrect creator/factory/quote/fee/recipient/holder rewards; unbound operations; WETH unwrap rollback; native receive funding; forced ETH and token donations; ERC-20 return values; and maximum supply with two centuries of simulated time.

The reference oracle uses explicit per-account age updates and allocates scaled rewards separately on every funding. It never uses `ageIndex`, `timeIndex` or cumulative checkpoint integration. Seven accounts run 1,000 sequences of 96 randomized events, including same-block changes, partial/full exits, tiny fundings, WETH, claims and donations. Every step checks exact account principal, age, claimable ETH, claimed ETH and global solvency; every sequence ends with full principal/reward unwind. Integer precision is intentionally the same specified funding-index floor, so this verifies implementation against the integer specification rather than guaranteeing zero dust relative to rational arithmetic.

Default suite: **25 Solidity tests passed**, including 1,000 conservation fuzz cases, 1,000 oracle sequences and 25,600 invariant calls with zero reverts. A second seeded CI-profile run uses **5,000 conservation fuzz cases, 1,000 oracle sequences and 76,800 invariant calls**, with unexpected handler reverts treated as failures. **Seven JavaScript tests passed**. The local browser lifecycle also passed, including actual mined CREATE identity, admin bind, deposit, creator-fee flow, external funding refresh, claim and full exit.

## Round 3: static analysis and platform/deployment rehearsal

Slither **0.11.6** ran twice, before and after hardening, with **102 detectors** over seven production/interface contracts. The final scan emits **14 diagnostics** and exits nonzero because diagnostics remain. None were silently filtered beyond test/script/dependency paths; it is not reported as a clean zero-warning scan.

| Detector                        | Count | Disposition                                                                                                                                                                                                         |
| ------------------------------- | ----: | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| weak-prng (tool: high)          |     1 | False positive. Modulo retains a fractional accounting remainder; no randomness is requested or used.                                                                                                               |
| reentrancy-balance (tool: high) |     1 | Guarded balance-delta check around deposit. Hostile token callback test proves reentry reverts and mismatch rolls back all state. Binding additionally restricts the actual launch token through the official Hook. |
| divide-before-multiply          |     1 | Required floor of the funding index, reused consistently by the time index. Moving the floor changes the economic formula. Independent oracle verifies the documented rounding.                                     |
| incorrect-equality              |     4 | Explicit zero amount, zero eligible age or zero funding-index checks. These do not compare an externally manipulable ETH balance against a required fixed amount.                                                   |
| write-after-write               |     1 | `receive` enters and releases the guard; `_fund` performs accounting only. The WETH-only path returns before writing storage to support canonical WETH's stipend.                                                   |
| missing-zero-check              |     2 | Creator zero is rejected by the inherited Admin constructor. Zero pending administrator intentionally cancels a proposal; it cannot accept the role. Both paths tested.                                             |
| reentrancy-benign               |     1 | `fundWeth` is guarded; canonical WETH is a configured dependency and its receive callback only accepts ETH. No-age failures roll back unwrap and funding.                                                           |
| timestamp                       |     1 | Weight intentionally uses block time. Same-block zero age is tested; the protocol makes no claim about real-world screen time.                                                                                      |
| low-level-calls                 |     2 | Deliberate optional-return ERC-20 handling and checked ETH payout. Failure/invalid returns and recipient rejection are tested.                                                                                      |

The official-platform mainnet fork lifecycle is simulated locally: deploy companion → launch 3% WETH-quote token → bind → trade → deposit → claim creator WETH → unwrap → fund → withdraw → collect ETH. The actual Solidity deployment script is also rehearsed against mainnet state without `--broadcast` or a signer. Read-only preflight verifies current platform relationships and the 1% platform / 2% creator split.

## Remaining trust and economic limits

- Contributions are discretionary. The contract does not force the creator to forward trading fees or guarantee returns.
- Time weight is uncapped. Older/larger positions can dominate and funding timing is observable/strategic. Zero-age protection prevents same-block flash reward capture, not all advance-positioning strategies.
- Downward rounding leaves dust; forced ETH and direct token donations are not recoverable/distributable through an admin sweep. Small funding can revert when its scaled increment is zero.
- Stockereum and canonical WETH remain external dependencies. Binding is irreversible and assumes the official Hook's launch registry remains a trustworthy attestation.
- No keystore was opened, no private key was requested/read and no mainnet deployment exists as a result of this work. Final deployment must use the project's owner's local signer and be source-verified on Etherscan before token launch.

## Reproduce

```powershell
forge build --sizes
pnpm test
$env:FOUNDRY_PROFILE = 'ci'
forge test --no-match-path contracts/test/fork/* --fuzz-seed 0x20261101
Remove-Item Env:FOUNDRY_PROFILE

pnpm test:e2e
pnpm preflight:mainnet
uv tool run --from slither-analyzer slither . --json .e2e/slither-review.json
```

Slither cleans/rebuilds Foundry output. Run it separately from other Forge commands, and rebuild before artifact-dependent tests if needed. Test-only `selfdestruct` deliberately exercises forced ETH; no production contract contains that operation.
